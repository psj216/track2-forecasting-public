# Single frozen mechanism
MOONSHOT20-SPIKE70 uses the exact archived FF03 as its base. The original FF03 entrypoint completes all numeric and F1/F4 text processing before postprocessing.
For an explicit, nonconflicting daily level contract, 1000 complete joint scenarios and unique finite as-of-bounded anchors, NumPy default_rng(seed).permutation(sorted draw IDs) chooses exactly 700 scenarios. Every cell in each selected scenario becomes anchor + 0.20*(FF03 value-anchor). The other 300 scenarios stay exactly unchanged. Draw identifiers, asset/horizon keys, row order and count stay unchanged. No realized values or model selection are involved.
Monthly, nonlevel, conflicting contracts, non-1000 draw counts and missing/ambiguous/nonfinite anchors bypass unchanged. Anchor cadence is conservatively checked from input dates (at least 30 observations, median spacing <=3 calendar days). This may bypass a valid sparse daily input; it cannot improve performance selectively using outcomes.
The name 'spike' denotes a concentrated component, not a literal point mass. The 30% original component is not a guarantee of unchanged tail quantiles, tail loss or shock protection. F1/F4 effects are also compressed relative to anchors for selected scenarios.
Only adapter.py is copied into the new layer. The existing forecast launcher is replaced in the NEW image only; it calls the unchanged /opt/finalfit03/candidate_monthly.py. Audit messages go to stderr, never extra files in the output directory.
